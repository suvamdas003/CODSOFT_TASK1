# Audit and remediation — October 2026

Scope: full repository review (source, Prisma schema and migrations, authentication,
authorization, services, route handlers, validation, tests, Docker, environment files,
documentation, dependencies, Git/Docker exclusions), followed by fixes and verification.
"Reproduced" means the defect was demonstrated on the unmodified code before fixing; every
code defect has a regression test in `tests/integration/regressions.test.ts`,
`tests/integration/create-admin.test.ts` or `tests/unit/auth-secret.test.ts` that fails on
the original code and passes now.

## Verified correct (no change needed)

- Server-side RBAC in every service; record-level checks for teachers (assigned sections,
  subject-level marks) and students (own records only, IDOR returns _not found_). Every page
  and route handler requires the right role.
- Better Auth: no public sign-up, `/update-user` cannot change `role` or `isActive`,
  origin/CSRF checks on, HttpOnly + SameSite=Lax (+ Secure in production) cookies, sessions
  re-validated against `isActive` on every request, sessions deleted on deactivation.
- Integer minor-unit money handling, `SELECT … FOR UPDATE` on payments, idempotency keys,
  advisory locks for bulk invoicing, database CHECK constraints (paid ≤ total, positive
  amounts, marks ≤ maximum checked in the service, pass ≤ max marks).
- Attendance uniqueness (`studentId, sectionId, date`) with upserts; percentage policy.
- Referential integrity (`onDelete: Restrict` on academic and financial history), soft
  deactivation instead of deletion, append-only audit log written in the same transaction.
- Parameterized SQL only, CSV formula-injection protection, generic error messages.

## Remaining risks and recommendations

- `npm audit` reports 9 high-severity advisories, all in development tooling:
  `eslint-config-next` → `fast-glob`/`micromatch`/`braces`, and the `prisma` CLI →
  `mysql2`, `deepmerge-ts`. npm's suggested fixes are major **downgrades**
  (`eslint-config-next@14`, `prisma@6`), so they were not applied. None of these packages
  are in the runtime app image; the migrator image contains the Prisma CLI (its MySQL driver
  is never used with PostgreSQL). Re-check when Next.js/Prisma publish patched releases.
- Attendance is unique per student, section and day, so a student moved between sections
  during a day can have one record in each. This is intentional; change the unique key only
  if your school needs one record per student per day.
- Section result lists show students by their current section; after promotion, history
  stays on report cards and the student profile, not under the old section.
- Percentages are rounded to two decimals before the grade band is chosen (89.995 % shows
  and grades as 90.00 %). This avoids floating-point boundary errors; adjust
  `src/lib/utils/grades.ts` if your policy requires truncation.
- The per-account lock can be triggered deliberately to keep a user out for 15 minutes
  while an attacker keeps failing. Administrators can lift it with a password reset.
- No Content-Security-Policy header is set. Add one at the reverse proxy if required.
